# Dentiva Pro V1.1 — Independent Audit Plan

**Session type:** independent end-to-end production audit (install → use → break → fix → re-test → final commercial release).
**Target release:** Dentiva Pro **V1.1** (version `1.1.0`) — final hardening release; feature freeze thereafter.
**Date established:** 2026-09-28.
**Baseline:** V1.0.0 release — tag `v1.0.0`, release commit `97e1124` (artifact commit `74fc65d`),
installer `DentivaPro-Setup-1.0.0.exe`, SHA-256 `2cd574b86a968007093c5463c55c1844ec579090c039bf59076b2330675ef838`.

## 0. Absolute rules

1. V1.0 reports are *evidence*, not truth. Every claim is re-verified independently.
2. No success claims without artifacts: real test output, real CI runs, real installer validation.
3. Environment honesty: distinguish **Automated / CI / local-sandbox / physical-hardware / environment-unavailable** for every validation. Physical printer, physical DPI, and real Windows hardware are *not* available in this sandbox — CI on `windows-latest` is the Windows evidence channel.
4. Feature freeze: V1.1 = hardening + polish. New capability only when required for safety, security, data integrity, commercial usability, workflow completeness, legal/operational correctness, or production reliability — each such addition justified in the Fix Log.
5. Root causes only. Never weaken or delete a test to make it pass. No hidden failures.
6. The activation secret must never appear in source, docs, tests, logs, or this plan.

## 3. Phases

- **Phase A — Recon & static audit (read-only).** Systematic line-by-line review of all 21 services, IPC router, schema, preload, and 20 renderer pages. Test-quality review (can tests falsely pass?). Permission-matrix mapping. Docs accuracy audit.
- **Phase B — Dynamic break audit.** New integration tests written *against* each uncovered module (writing tests is finding bugs): RBAC attack matrix, financial immutability, unlimited-records stress fixture, backup/restore adversarial cases, date/boundary/report-accuracy checks. E2E expansion for critical journeys (prescription → print, queue, appointment lifecycle). Realistic synthetic clinic dataset (hundreds of patients) for scale checks.
- **Phase C — Fixes.** Per register: reproduce → root-cause → fix → targeted test → regression. Dependency upgrades only when necessary, safe, tested (Electron → supported major; react-router → 7.x; dev-dep cleanups as compatible).
- **Phase D — Second independent audit.** Re-read the master specification fresh; re-inspect everything including fixes; look for new problems introduced by fixes; verify no fake UI, no dead code, no TODOs.
- **Phase E — Build, install, release.** Bump `1.1.0` everywhere; full CI (verify/e2e/package+smoke); validate V1.1 `.exe` (silent install, activation→setup→login→core-journey smoke, uninstall); checksum triangulation; GitHub Release `v1.1.0` with installer + SHA256SUMS + release notes; final reports.

## 4. Persona audits (Phase B/D)

Owner (setup, config, staff, permissions, reports, backup/restore, audit log) · Dentist (chart, visit, prescription, print, follow-up) · Receptionist (registration, appointment, queue, lookup) · Accountant (invoices, payments, expenses, reports, permission boundaries) · Inventory (purchase, stock-out, expiry, low stock) · Unauthorized staff (every financial/salary/user-management/destructive/audit/backup path must be denied at the service layer).

## 5. Severity model

P0 release blocker (data loss/corruption/security bypass/broken install|activation|auth|restore/crash) · P1 critical (major workflow unusable, financial error, prescription/history/printing breakage, serious permission issue) · P2 major (UX, validation, performance, confusion, visual defect) · P3 minor (cosmetic) · P4 enhancement (out of scope unless justified under §7 of the mission).

## 6. Environment limits (honest disclosure, restated in every report)

- No physical printer, no physical DPI sweep, no real multi-monitor, no standard-user/admin Windows matrix locally.
- Windows evidence = GitHub Actions `windows-latest`: unit/integration (vitest), Playwright E2E on the packaged app, NSIS silent install + installed-artifact smoke + uninstall.
- Offline audit = code-level guarantee (no runtime network code, CSP `connect-src 'none'`) + CI execution environment.
- Anything not verifiable here will be listed as **environment-unavailable**, never as passed.
